# 管线细节

## 1. 采集（`collect/`）

- `sheets`：把字符集排成"一次一格"的清单 `manifest-<tag>.json`，每格有 id / char / pass。
  `--order char-major` 让同一个字连写几遍（一屏四格同一个字，写得快）；
  `pass-major` 是整本写完再写下一遍。`--no-pdf` 只出清单（手机写）。
- `desk`：一份自包含 HTML。一屏 4 格，笔迹 = 矢量点序列（含压力），
  面板里有圆头/书法收放（perfect-freehand 的思路：streamline → 半径 → 弧长渐细）。
  数据先落 IndexedDB，再经 JS 桥落到 App 目录（`Android/data/inkcell.desk/files/glyphs/`），
  拔线也能 MTP 拷出来。文件才是进度的真相：删掉某格文件 = 这格重新排进队列。

压感→粗细的三个参数（决定"看起来轻重"）：

| 参数 | 含义 | 经验值 |
| --- | --- | --- |
| `rmax` | 最大笔尖半径（em） | 0.030–0.034 |
| `rmin` | 最轻时占 rmax 的比例 | 0.20（0.42 会把对比压平） |
| `easing` | 压力曲线指数 | 0.85–1.0 |

一只 4096 级压感的板子，写出来的原始压力 p5–p95 大约 0.11–0.46。
`rmin=0.42` 时全范围只有 1.3× 粗细差，印到 10.5pt 就是"看不出差别"；
`rmin=0.20` 能到 2.9×。

## 2. 入库（`glyph/`）

- 每格按**墨迹包围盒**归一化到 em 方框（汉字 0.86 em，拉丁 0.68 em），
  记 `dx/dy/adv`，写 `glyphs/<hex>_v<k>.png` 与 `index.json`。
- **竖向必须按写出来的位置放**（`ybot` 来自原始笔迹）：
  一律"墨迹底边贴基线"会让 `一`、`：`、`→`、`——` 掉到基线上变成下划线。
- **小标记按天然尺寸**：`·`、`'`、`"` 只有 0.11–0.25 em，按拉丁字母放大 6 倍就是黑团。
- `from_strokes` 直接吃矢量笔迹重渲，不用重新写就能换粗细/压感参数；
  `--weight` 按每字平均压力做跨字重量补偿（0.35 大约把跨字对比从 1.02× 提到 1.2×）。

## 3. 回填（`render/` + `doc/`）

- 模板的"条目 + 空行"结构被当成插槽：`条目段落` 决定写什么，`紧跟的空段落` 决定写几行。
- 每行单独渲一张条带图（`render_bands`），贴进对应空段落，再转成**浮动图**
  （`anchor.py`：`behindDoc` + `wrapNone` + 相对锚点），所以行高和分页完全不受影响。
- 断行宽度必须扣掉 Writer 的左右页边距，否则行尾溢出画布、最后一个字被裁掉；
  表格总宽超版心时先收紧列间距、再缩字号。
- 出条后 `_safe()` 兜底：墨迹离画布边不足 4px 就平移，实在放不下才微缩。
- `verify`：段落数、`exact` 行距数、inline 图数、每张图宽高比、格子图贴边数、
  以及"每个条目是否真的填了东西"。

## 4. 为什么不用 TTF

渲染管线本来就是 PIL 位图（字形 = 一张灰度 mask），所以字库不需要字体文件，
也就不需要 FontForge / 几千字的切字与基线校准。代价是只能用于"我们自己渲染"的场景
（生成图片贴进文档），不能拿去当系统字体用——这正是本项目的用途。
